1. Resolve repository-owned panel findings and open phase work. If a finding
   cannot be resolved, preserve dissent and leave the track open.
2. Continue the daily cumulative beta campaign. A material candidate or
   instrumentation change resets the qualification epoch; ordinary commits do
   not manufacture or erase elapsed time.
3. Freeze an authoritative public workload manifest and measure resource and
   cost envelopes. If that cannot be sourced, run national-volume synthetic
   tests but prohibit nationally representative claims.
4. Execute production-representative recovery with measured RPO/RTO. The
   existing GitHub drill remains technical-preview evidence; Hugging Face can
   be retried after prepaid credit exists.
5. Freeze the release candidate only after upstream gates pass, then start its
   30-day exact-revision soak. Otherwise defer RC.
6. Use agent panels for all code, methods, scientific and evidence review.
   Operator/user records are separate factual workflow observations, not
   reviewers. If those higher-tier criteria are retained and absent, remain a
   technical preview.
7. Assemble a digest-bound promotion/deferral/rejection packet for the single
   accountable owner. Without that record, do not promote.

## Library decision

Retain DuckDB, PyArrow, PyProj, Shapely, HTTPX and JSON Schema. Add `pyperf` and
`psutil` only when the national benchmark harness actually consumes them. Add
`huggingface_hub` or `fsspec` only for tested in-process Hub access. Do not add
Datasets, GeoPandas, Locust, ASV, Pandera or Frictionless now: none supplies the
missing authority, elapsed time, production recovery, participant facts or
release decision, and each expands the dependency and audit surface.
