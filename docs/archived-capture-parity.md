# Bounded capture migration across Python and Node

The experimental archived capture view now has a second implementation in
`scripts/capture_migration_node.mjs`. It validates source identity, optional facet
references and the view hash before returning a migrated or recovered object.
It preserves native extensions and uses UTF-16 key ordering and JSON number
serialization for the bounded RFC 8785 inputs. Invalid Unicode and non-finite numbers are rejected. The harness starts from
Python-validated values: Python rejects unsafe integers before serialization,
while finite floating-point values such as 1e20 remain supported. Node cannot
recover Python integer-versus-float distinctions after JSON parsing, so this
runner does not establish arbitrary raw-number parser parity.

All 236 archived Stats NZ capture wrappers produce identical Python/Node view
values and hashes. Node recovers Python views and Python recovers Node views to
the original native objects. The tests also compare rejection of 15 malformed
source/view/facet cases and exercise Unicode keys, decimal/exponent numbers,
nested digest fields and evidence references. Python whitespace semantics are
explicitly matched rather than relying on JavaScript trim behavior.

The Node tool is a structured-object conformance runner. Its JSON request batch
is generated by the Python harness. It is not an untrusted JSONL parser, storage
adapter or independently operated clean-room reproduction. The existing Python
adapter retains responsibility for duplicate-key rejection and atomic file
creation. References still confer no rights or authority. Full provenance-event
parity, broader native families, candidate qualification and maturity promotion
remain open. Historical migration and release evidence is unchanged.

Reproduce the digest-bound receipt:

```bash
uv run python -m scripts.build_capture_parity_evidence --output /tmp/capture-parity.json
```
